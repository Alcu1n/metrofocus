## 组件与行为

| 组件 | 结构与状态 | 原生实现位置 |
| --- | --- | --- |
| 未发车票面 | 标签、可编辑任务、3 个带区间数的班次、行程摘要、尚未发车标识 | `StationView.swift` 的任务与服务选择区域 |
| 线路选择 | 4 个有文字的色点选项；选中同时改变底色与文字，不仅靠颜色 | 保留原有 `TransitLine` 状态及处理逻辑 |
| 主操作区 | 固定在内容下方；摘要和候车说明位于按钮上方；空任务显示错误并聚焦输入 | 沿用出发校验与现有引擎入口 |
| 日分组票夹 | 最新日期在前；每张票显示线路、任务、抵达时间、班次代码、专注分钟、到站/验票状态 | `CollectionViews.swift` / `TicketLibraryView`、`TicketRow` |
| 空票夹 | 无票时显示原有空状态文案和去车站入口；统计为 0；不显示示例票 | 保留原有 tab 跳转行为 |
| 车票详情 | 同一纸张与分隔规则；展示日期、出发/抵达、站数、专注时长、状态印章 | `TicketViews.swift` / `TicketFace`、`TicketDetailView` |
| 打孔反馈 | 用户明确操作后出现孔位，印章从 ARRIVED 改为 VALIDATED，列表同步更新 | 保留现有打孔按钮、长按、幂等与持久化行为 |
| 设置/编排弹层 | 复用车站原型；表单取消不得更改已保存选择 | 不改业务默认值或休息计算 |

原型只用内存样例展示详情与打孔状态。原生的导航返回、长按打孔、分享/导出、倾斜触感与保存语义全部继续沿用已有实现；这轮详情弹层用于验证票面组件，不构成替换原生导航或删除功能的决定。

加载、网络失败状态不适用于本轮的本地静态样例，未虚构加载骨架。输入错误、空列表、未验票/已验票、普通/长任务已覆盖。

## 平台与无障碍实现要求

- 保持夜间主题。页面顶部、底部继续使用真实安全区与系统 TabView；浏览器模拟状态栏不进入产品代码。
- 中间区域可滚动；小屏或长文本增加内容高度，不能靠缩小字号隐藏信息。表单键盘避让仍需原生验证。
- 将文字映射为可缩放系统样式或 `@ScaledMetric`。Dynamic Type 大字号下，班次可改为纵向选项；原型未验证 Dynamic Type，实施时须另验。
- 票根辅助功能名称组合任务、线路、分钟数与验票状态；装饰侧孔、撕线和条形码不重复朗读。原生 VoiceOver 焦点和阅读顺序须实测。
- Web 原型支持键盘焦点、弹层 Tab 循环、Escape 关闭并返回触发票根。原生保留标准返回、关闭和长按等手势的共存。
- 状态文字与勾选符号辅助区分，不只使用颜色。未以浏览器截图宣称完整无障碍合规。

## 动效

不增加展示性动画。当前原型仅有 180 ms 的按钮背景/文字颜色过渡和按下缩放至 0.98，允许中断。`prefers-reduced-motion` 下关闭过渡；打孔状态直接显示。后续 SwiftUI 保留项目现有声音、触感、撕票/打孔与 Reduce Motion 行为；是否微调需依据选定界面的实际设备效果，不在本轮替换。

## 第二页迁移结论与验收

车站是「填写任务并发车」的单票表单；票夹是「按日期回看多次旅程」的分组列表。复用纸色、墨色、线路编号、撕线、圆角、字体与 tab 栏，只新增紧凑票根和日期分组，不将首页表单机械复制为列表。

独立截图评审：两页视觉规则一致，无必须修复项。程序交互核验覆盖两页 × 中英 × 402×874 / 375×667，共 8 组；无横向溢出、按钮至少 44 px、底部导航在视口内。验证第三张票可滚动完整到达，打开详情、打孔、列表状态同步及焦点返回；另验证空票夹跳转车站、任务校验、线路/班次与出发预览。`verification/c-results.json` 保存结果，`verification/replay-c.js` 可复验。

以上为浏览器原型阶段的验证边界。用户确认后已继续原生实现，键盘、Dynamic Type、旅程、持久化和分享的独立原生证据见验收记录；VoiceOver 与真机触感仍待专项验收。
